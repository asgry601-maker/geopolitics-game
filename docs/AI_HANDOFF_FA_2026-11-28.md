# سند تحویل پروژه — ۲۸ نوامبر ۲۰۲۶

> این سند برای انتقال وضعیت فنی پروژه به همکار یا دستیار توسعه بعدی تهیه شده است. وضعیت‌ها بر اساس آخرین اطلاعات ثبت‌شده در گفتگو و شناسه‌های commit موجود هستند؛ هر توسعه‌دهنده باید پیش از تغییر کد، شاخه و فایل‌ها را دوباره از GitHub دریافت کند.

## مخزن و محیط اجرا

- مخزن: `asgry601-maker/geopolitics-game`
- شاخه کاری ثبت‌شده: `phase-B-dashboard-development`
- مسیر اصلی کد: `phaseA/`
- موتور: Python 3.8
- رابط: JavaScript قدیمی سازگار با مرورگرهای قدیمی؛ کد جدید باید ES5 بماند.
- سیستم هدف کاربر: Windows 7 نسخه ۶۴ بیتی و سخت‌افزار قدیمی؛ سازگاری WebGL1 باید حفظ شود.
- فایل‌های کلیدی:
  - `phaseA/engine/geopolitics.py`
  - `phaseA/geopolitics_api.py`
  - `phaseA/world/world.js`
  - `phaseA/world/world.html`

## وضعیت کلی فازها

- فاز A: زیرساخت اولیه جهان و نقشه کشورها تکمیل شده است.
- فاز B: داشبورد و سامانه‌های مدیریتی/سیاسی/دیپلماتیک تکمیل شده و آزمون نهایی آن را کاربر با موفقیت تأیید کرده است.
- فاز C: هنوز رسماً آغاز نشده است. موضوعات برنامه‌ریزی‌شده آن شامل زیرساخت، منابع، صنعت و مدیریت استانی هستند.
- فازهای بعدی طبق نقشه راه پروژه شامل سامانه‌های تکمیلی، جهان پویا و اتصال هوش مصنوعی زنده هستند. هوش مصنوعی زنده تا زمان فعال‌سازی رسمی فاز مربوطه نباید شبیه‌سازی یا جعل شود.

## قابلیت‌های تکمیل‌شده و تأییدشده

### سیاست داخلی
- طبقه‌بندی سیاسی پایه برای ۱۷۴ کشور، با snapshot مورخ ۲۰۲۶-۱۱-۰۵.
- تفکیک وضعیت پایه از وضعیت جاری بازی.
- ویرایش ساختار سیاسی کشور بازیکن از طریق API.
- سامانه پیشنهاد اصلاحات سیاسی، بررسی امکان‌پذیری، تصویب/رد، اجرای مرحله‌ای، هزینه و پیامدهای داخلی.
- تشخیص وضعیت بحرانی حکومت و نگاشت نهاد مرتبط بر اساس ساختار سیاسی؛ این تشخیص به‌تنهایی به معنی وقوع قطعی تغییر حکومت نیست.
- زبانه تریبون تا زمان فعال شدن هوش مصنوعی زنده قفل می‌ماند.

### رویدادها و مدیریت
- زیرساخت مرکزی رویدادها با دسته‌بندی‌های سیاسی، اقتصادی، تجاری، نظامی، اجتماعی، دیپلماتیک، طبیعی، محیط‌زیستی و هسته‌ای.

- فعال‌سازی خودکار محرک‌ها و پیامدهای کامل رویدادها هنوز به مراحل بعدی موکول است.

### دیپلماسی و ارتباطات
- تحریم‌های بازیکن با دسته‌بندی‌ها، تاریخچه و لغو.
- پیمان‌ها و پیشنهاد توافق با پذیرش مرحله‌ای و امکان لغو یک‌طرفه در موارد تعریف‌شده.
- اتحادها، درخواست عضویت و خروج از اتحاد.

- نشست‌ها و گفتگوهای مشترک با شناسه نشست، طرف‌های شرکت‌کننده، موضوع، تاریخ و وضعیت.
- حالت‌های بیانیه عمومی، مذاکره عادی و محرمانه با معناهای رسانه‌ای جداگانه.
- تقویم پویا برای فرایندهای زمان‌دار و شمارش معکوس.
- گفتگوی واقعی با هوش مصنوعی تا فاز فعال‌سازی هوش مصنوعی زنده قفل است؛ هیچ پاسخ ساختگی یا ازپیش‌نوشته‌شده‌ای نباید جایگزین آن شود.

## کار بعدیِ باز و ناتمام

بسته سومِ به‌روزرسانی فناوری هنوز پیاده‌سازی نشده است:
- تهیه یک شاخص کلی فناوری/نوآوری ملی برای ۱۷۴ کشور، با مقدار ۰ تا ۱۰۰.
- استفاده از داده‌های معتبر بین‌المللی در موارد موجود و برآورد شفاف برای کشورهایی که داده کافی ندارند.
- همراه هر مقدار، نوع داده (مشاهده‌شده/برآوردی/ترکیبی)، سال مرجع، منابع و درجه اطمینان نگهداری شود.
- منابعی که در بررسی قبلی شناسایی شده‌اند: شاخص جهانی نوآوری WIPO، شاخص توسعه ICT اتحادیه بین‌المللی مخابرات (ITU) و داده‌های تحقیق‌وتوسعه بانک جهانی/UNESCO.
- هیچ عددی نباید بدون ثبت منشأ و روش تخمین به‌عنوان داده قطعی معرفی شود.
- پیش از تغییر کد، فایل‌ها و SHAهای فعلی شاخه دوباره دریافت شوند.

## قواعد فنی مهم

1. پیش از هر تغییر، نسخه فعلی فایل را از شاخه کاری دریافت و SHA جاری را استفاده کنید.
2. تغییرهای یک فایل را موازی ننویسید؛ پس از هر نوشتن، فایل را دوباره دریافت و نتیجه را بررسی کنید.
3. کد JavaScript باید با مرورگر قدیمی و ES5 سازگار بماند؛ از `let`، `const`، arrow function و APIهای جدید ناسازگار پرهیز شود.
4. Python باید با نسخه 3.8 سازگار باشد.
5. حفظ داده‌های ذخیره‌شده و migration ذخیره‌های قدیمی ضروری است.
6. هر قابلیت مرتبط با هوش مصنوعی باید تا فعال‌سازی رسمی فاز هوش مصنوعی زنده قفل بماند؛ پاسخ یا تصمیم ساختگی تولید نشود.
7. پس از هر بسته، دستور آزمون محلی روشن و محدود به کاربر داده شود و تا تأیید او بسته بعدی شروع نشود.
8. فاز B بسته‌شده است؛ قابلیت‌های جدید پیش از فاز C باید به‌عنوان بسته‌های الحاقی مستقل ثبت شوند.
