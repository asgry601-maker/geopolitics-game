- **منبع:** [geoBoundaries](https://www.geoboundaries.org) — نسخه `gbOpen`، سطح `ADM1`
- **API:** `https://www.geoboundaries.org/api/current/gbOpen/{ISO3}/ADM1/`
- **Commit قفل‌شده داده:** `9469f09` (شاخه releaseData در مخزن wmgeolab/geoBoundaries)
- **تاریخ دریافت:** 2026-11-24

### مجوز هر کشور متفاوت است

### شرایط بازنشر (ZIP بازی)
- **انتساب الزامی برای همه** — متن انتساب هر کشور (فارسی) در `LICENSES.json` فیلد `attribution` آمده؛
  رعایت انتساب با انتشار همین دو فایل (`README-PROVINCES.md` + `LICENSES.json`) برآورده می‌شود.
- **ShareAlike (۸۲ کشور: ODbL + BY-SA):** مشتقات این بخش‌ها اکیداً باید تحت همان مجوز منتشر شوند؛
  داده ساده‌شدهٔ ما مشتق محسوب می‌شود. برای توزیع غیرتجاری/اتحادیه‌ای بازی، انتساب کامل عملاً کافی است،
  اما اگر روزی نسخه تجاری یا داده‌های استخراجی جدا فروخته شود، باید مجوزِ همان کشور برای بخش آن کشور رعایت شود.
- کل لایه geoBoundaries به‌صورت کلی «CC-BY 4.0 است» ادعا **نکنید** — این ادعا نادرست است.

## ساختار
```
phaseA/data/provinces/
  index.json        ← فهرست: {ISO3: {n, bbox, v}} + totals + no_data
  IRN.json          ← یک FeatureCollection GeoJSON استاندارد به ازای هر کشور
  USA.json
  ...
```

هر `Feature` استان شامل:
| فیلد      | توضیح |
|-----------|-------|
| `id`      | شناسه یکتا و پایدار (shapeID از geoBoundaries) |
| `iso`     | کد ISO 3166-2 (مثل `IR-07`)؛ ممکن است برای برخی خالی باشد |
| `name_en` | نام انگلیسی رسمی استان |
| `name_fa` | نام فارسی؛ **فعلاً فقط ایران (۳۱/۳۱) پر شده** — سایر کشورها منبع معتبر جداگانه می‌خواهند |
| `country` | ISO3 کشور مالک |
| `geometry`| Polygon یا MultiPolygon (ساده‌شده) |

## ساده‌سازی
- الگوریتم: Douglas–Peucker بدون recursion، شروع از tolerance = `0.02°` (سقف `0.32°`)
- **سقف ۵۰۰۰ رأس در هر کشور:** اگر عبور کند، tolerance دوبرابر (تا ۶ مرحله) و حلقه‌های
  زیر `tol²` درجه مربع حذف می‌شوند؛ **به‌جز KEEP_TOP_ISLES=۴ جزیرهٔ بزرگِ ریزتر**
  هر استان که همیشه حفظ می‌شوند (مرتب از مساحت واقعی مثلث‌بندی مبدأ-محور).
- نویز نقشه‌برداری (مساحت < `1e-8` درجه²) همیشه حذف و در آمار گزارش می‌شود.
- همه حلقه‌های خروجی **بسته‌اند** (استاندارد GeoJSON) — تست‌شده.
- نتیجه نهایی: **۱۷۴ کشور، ۳۰۰۴ استان، ~۲۱۴٬۵۰۰ رأس، ~7.4MB** — سازگار با کش lazy در B2

## کشورهای جزیره‌ای و point-only فاز A
هر ۹ کشور point-only قبلی (بحرین، مالت، مالدیو، سنگاپور، موریس، کیپ‌ورد، باربادوس،
ساموآ، تونگا) در این پایگاه داده **polygon استان دارند** (بحرین = ۴ استان تأیید شد).
هیچ کشوری وابسته به نقطه‌نما باقی نمانده است.

## نحوه بازسازی
```bash
python3 phaseA/tools/build_provinces.py --budget 240     # حلقه resumable (cache در /tmp/gb_raw)
python3 phaseA/tools/build_provinces.py --index          # بازسازی index.json
python3 phaseA/tools/build_provinces.py --report         # گزارش حجم/پوشش
```
- نیاز: python 3.8+ فقط کتابخانه استاندارد، **شبکه** (بدون بستگی به curl — urllib)
- cache خام در `/tmp/gb_raw/<ISO3>.json` و metadata در `/tmp/gb_meta/<ISO3>.json`
  برای الحاق مجدد بدون دانلود دوباره

## محدودیت‌ها و نکات
1. **نام فارسی فقط ایران** سیستماتیک شده؛ برای سایر کشورها در فازهای بعد نگاشت دستی/منبع جدا لازم است.
2. تعداد استان‌ها معمولاً = admUnitCount اعلامی geoBoundaries؛ انحراف فقط ناشی از حذف ویژگی‌های
   بدون هندسه یا نام تکراری است (در ایران ۳۳→۳۱؛ در گزارش اسکریپت ثبت می‌شود).
3. برخی بایگانی‌های geoBoundaries با `admUnitCount` مقدماتی کمی متفاوت‌اند؛ داده «current» مبنا بود.
4. هندسه ساده‌شده است — برای نمای جهانی و باز-zoom معمولی بازی کافی؛ دقت رسمی/نظامی حامل نیست.
5. کشورهایی که change-case دارند (مثل چند جزیره دو-متعارف) با شکل رسمی geoBoundaries بازسازی می‌شوند.
